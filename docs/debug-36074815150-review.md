Reviewed 2026-09-25. This is a measurement-development record, not a
confirmatory result or a test of a neural mechanism.

**Decision: run another debug before freezing the 888-item pilot.** The
workflow completed, but numerical judgments are not interpretable as stable
valuation estimates under the response protocol used in this run.

## Response format and numerical option order

| Evidence family | Requests | Parsed A | Parsed B | Unparsed |
|---|---:|---:|---:|---:|
| Attribution | 100 | 51 | 49 | 0 |
| Matched-aggregate numerical evidence | 96 | 0 | 56 | 40 |
| Total | 196 | 51 | 105 | 40 |

All 40 unparsed responses are short prose fragments: `I need to analyze`
(24), `I need to determine` (13), or `I need to in` (3). That is 20.4% of all
requests and 41.7% of numerical requests. They are not evidence of refusal.
The four-token allowance plausibly cut them off, but the original runner did
not record API stop reasons, so truncation cannot be confirmed retrospectively.

All 56 parsed numerical answers are the letter B. Of the 48 numerical
option-order pairs, 24 have two parsed answers, eight have one, and 16 have
none. **All 24 complete pairs disagree semantically when options swap.** A
literal B answer selects the partner's payoff in one order and the recipient's
payoff in the other. This prevents treating these answers as order-stable
tradeoff judgments. It does not show that Haiku lacks all capacity for the task.

The original inspection report divides disagreement counts by all presented
rungs, including rungs with missing answers. For example, zero disagreements
with no complete pair is not evidence of agreement. Version 0.4.2 reports the
number of complete pairs explicitly.

Missingness also removes conflicting answers selectively. Some aggregate
cells consequently receive a unique fitted bound despite the response-letter
pattern. Those bounds are conditional outputs of the threshold fitter, not
credible social-valuation estimates from this batch. No change to the scorer
or retroactive coercion of missing answers has been made.

## Attribution findings

All 60 valuation-ladder responses predict that the partner keeps the points,
across every cause and both option orders. All five cells therefore have a
left-censored fitted valuation below the lowest tested ratio, 0.1. The
unable-versus-unwilling contrast is unresolved; this is not evidence that their
underlying values are equal.

The binary probes each contain two option orders. Entries below are the
number of affirmative predictions out of two, not estimated population
probabilities or independent replications.

|---|---:|---:|---:|---:|
| Baseline | 1/2 | 2/2 | 2/2 | 2/2 |

| Helped | 2/2 | 2/2 | 2/2 | 2/2 |

The required same-task ability ordering is observed in this one debug
scenario. The required valuation ordering is unresolved. The proposed
dissociation has therefore not been demonstrated.

The unable partner is predicted to decline the same task despite the probe
stipulating future ability. That could reflect trouble with the conditional
or a reluctance inference; these binary answers do not identify why. Retain
it as an exploratory observation rather than rewriting it into agreement.

## Next debug protocol

Version 0.4.2 keeps the exact same user prompts, ladder, evidence,
counterbalancing, hypotheses and scoring. It changes response collection:

1. A system instruction specifies only the response format: "For each
   question, reply with exactly one uppercase letter: A or B. Do not include
   any explanation or other text."
2. The output allowance increases from 4 to 64 tokens, so unexpected prose
   can be inspected. This does not permit prose to be scored as A/B.
3. Each API response retains stop reason, returned model, request ID and
   token usage. Older records retain unknown metadata rather than invented
   values.
4. Inspection adds family-specific letter counts, API stop reasons, token
   totals, and complete-pair denominators.

Run a new **Inference debug** workflow on `main` with the same Haiku model;
do not use GitHub's Re-run jobs on the old revision. This is an explicitly
revised exploratory protocol. Do not resume or pool the original responses
with the new run. Both the response-format instruction and output allowance
change together, so any improvement cannot be attributed to one individually.

Review format compliance, truncation, answer-letter dependence and ladder
coverage before reading substantive contrasts. Do not require the predicted
psychological ordering as a criterion for a usable measure. If valuation
remains below the range, retain that observation; it may motivate a separately
documented range check or comparison model, not repeated tuning until a
preferred ordering appears. If numerical answers remain strongly dependent
on option order, a different measurement method or model is needed before
using those estimates in the essay.

The 888-item pilot remains unrun and unregistered. Its item hash alone does
not freeze the new system instruction or output budget: preserve the request
configuration and source revision as well.
