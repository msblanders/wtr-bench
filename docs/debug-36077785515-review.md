# Sonnet debug: audit and decision

Reviewed 2026-09-25. **Pause the 888-item pilot and calibrate the response
measure.** The planned comparison model completed every request, but showed
pervasive option-order dependence in its valuation answers. Increasing the
number of scenarios will not by itself resolve that problem.

## Comparison with the revised Haiku protocol

| Check | Haiku 4.5, second debug | Sonnet 4.5 |
|---|---:|---:|
| Parsed responses | 196/196 | 196/196 |
| Attribution valuation option-pair disagreements | 0/30 | 29/30 |
| Numerical valuation option-pair disagreements | 11/48 | 44/48 |
| Attribution valuation fits | 5 left-censored | 5 unidentified |
| Pooled numerical valuation fits | 3 left-censored, 1 unidentified | 4 unidentified |
| Required valuation contrast | Undetermined | Undetermined |
| Matched-totals LOW/HIGH contrasts | Both undetermined | Both undetermined |

Sonnet returned B on **151/156 valuation items**: 59/60 attribution items
and 92/96 numerical items. Every disagreement is B in both option orders.
For example, with identical evidence, it selects B when B gives you 10 points
rather than Sam 1 point; after swapping the options, it selects B when B
gives Sam 1 point rather than you 10. That is a different substantive
prediction about the same partner in the same situation.

The scorer correctly withholds point estimates from every valuation cell.
This is not a result showing absent social valuation, equal valuations across
conditions, or a causal mechanism. It demonstrates a limitation of this
measurement protocol on these particular debug cases. It also does not show
that Sonnet is generally worse at social reasoning than Haiku.

Entries count affirmative predictions across the two option orders; they are
not independent replications or population probabilities.

The score report counts the same-task ability ordering as consistent because
the unwilling condition has two affirmative predictions and the unable
condition one. However, the unable pair itself changes meaning with option
order: both raw answers are B. This is weaker evidence than the summary's
`1/1 consistent` entry might suggest. The report has not been altered, and
the proposed dissociation remains undemonstrated.

## Next step and cost

Synthetic checks verified what the program does with known response
patterns. They did not establish that the language models reliably interpret
these prompts. The debug stage has now identified that missing validation
step before any confirmatory responses were collected.

Use the separate [72-request calibration](inference-calibration.md) on
Sonnet, with known-answer controls and A/B versus recipient-name replies.
It checks answer mapping, quantity comparisons and explicit choice rules,
then includes a small selection of already examined debug cases. There is
no need to try a succession of models or run all 888 items now. The response
format comparison changes the reply instructions together with the output
labels, so its effects cannot be attributed to label tokens alone.

This audit preserves the original runs and does not revise their answers,
scoring, hypotheses or prompts. The new calibration is exploratory and does
not access the six confirmatory scenarios or two confirmatory numerical
constructions. No calibration API calls were made while preparing it.

Recorded Sonnet usage was 27,444 input tokens and 784 output tokens, with no
cache tokens. At [standard Sonnet 4.5 pricing](https://platform.claude.com/docs/en/about-claude/pricing)
of $3/$15 per million input/output tokens, that corresponds to **$0.094092**,
before account-specific adjustments or taxes. This calculation is not an
invoice lookup. The 888-item pilot remains unrun, unfrozen and unregistered.
